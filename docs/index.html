📚 SF Fantasy Shelf

A personal sci-fi and fantasy book tracking app — log your reading history, track series progress, and get AI-powered recommendations via Claude. Built as an Angular + Node monorepo deployed on Railway.

● Live on Railway Phases 0–5 Complete Angular 17 · Node/Express PostgreSQL · Claude AI

Overview

About the App

SF Fantasy Shelf is a personal book tracking app built for SFF readers. Log books you've read, track series progress, rate and review entries, and get personalised recommendations powered by Claude. The backend is a TypeScript Express API; the frontend is Angular 17 with Angular Material.

Frontend

Angular 17 standalone components, lazy-loaded routes, Angular Material (purple-green theme). Sidebar layout, responsive mobile hamburger.

Backend

Node.js 20 / Express 4 in TypeScript. Compiled to dist/. pg connection pool, auto-migrations on startup, Cloudflare R2 for covers.

AI

Anthropic Claude (claude-sonnet-4-5) via @anthropic-ai/sdk. Book summaries, "what to read next", and similar-author suggestions.

Infrastructure

Railway (Postgres plugin + two services), nginx serving Angular with $BACKEND_URL envsubst proxy, Cloudflare DNS.

Architecture

Request Flow

The browser loads the Angular SPA from nginx. All API calls use relative paths (/api/...) — in development these are proxied by the Angular dev server (proxy.conf.json) to localhost:3000. In production nginx uses envsubst to inject $BACKEND_URL at container startup, then proxies matching requests to the Railway backend.

Key Design Decisions

  • All list endpoints use a single SQL query with jsonb_agg + DISTINCT + FILTER — no N+1 queries
  • user_books.status uses VARCHAR + CHECK constraint, not a Postgres enum — avoids ALTER TYPE ADD VALUE locking on Railway rolling deploys
  • Two mirrored type files (backend/src/types.ts and frontend/src/app/types/schema.types.ts) — frontend omits password_hash
  • Claude system prompts use cache_control: ephemeral — repeated calls within 5 min cost ~10% of input tokens
  • Auto-migrations track applied files in a _migrations table — each SQL file runs exactly once

Features

Series Tracker

Compact cards — one per series — showing reading progress. Uses forkJoin to call /api/series and /api/books in parallel, then cross-references reading status to calculate progress.

  • Compact card layout — progress bar (3px), small thumbnail (22px), tight padding — mobile-first
  • Read count fraction (e.g. 2/5) inline with series name
  • Books ordered by series position; tap a book to open its detail dialog
  • Collapsible — shows first book by default, expand for full list
  • One-click "Add to Library" (want-to-read) on unowned series books
  • Series position supports decimals — book 1.5, 2, etc.

Features

Discover + AI

Two Claude-powered sections on the Discover page. Both call the backend which fetches user reading history from Postgres, builds a personalised prompt, and calls Claude with system-prompt caching.

What to Read Next

Calls POST /api/claude/next. Fetches the user's entire shelf (no limit), formats read/reading/want-to-read history ordered by rating, and asks Claude for 3 personalised recommendations with reasons. The more books in your library, the better the recommendations.

Authors You Might Enjoy

User selects an author from a dropdown. Calls POST /api/claude/similar-authors. Fetches AuthorWithBooks + reading history, returns 3 similar authors with style explanation.

Railway Gotchas

Full repo is always the Docker build context. Even with Root Directory set to backend, Railway sends the entire repo as build context. Dockerfiles use explicit paths: COPY backend/package*.json ./ and COPY backend/ .
DATABASE_URL is NOT auto-injected. Railway's Postgres plugin does not automatically share DATABASE_URL with other services. Copy it manually from Postgres → Variables into the backend service Variables.
nginx needs SSL options to proxy Railway backends. Add proxy_ssl_verify off, proxy_ssl_server_name on, and proxy_set_header Host $proxy_host — without these you get 502. Private networking (which avoids this) is not available on Hobby plan.
Rolling deploys kill enum migrations. ALTER TYPE ADD VALUE deadlocks on Railway. Use VARCHAR + CHECK for all type-like columns — already done throughout this schema.

Roadmap

Phase 0 — Foundation ✓
Angular 17 frontend, Node/Express TypeScript backend, full 12-table PostgreSQL schema, Angular Material UI, Claude AI integration, Railway production deployment.
Phase 1 — Auth ✓
JWT login/register/logout. bcrypt password hashing. AuthGuard on all routes. Profile & password management page. 30-day tokens persisted in localStorage.
Phase 2 — Book Management ✓
Google Books search + OpenLibrary fallback. Duplicate ISBN guard. Series auto-detection and auto-population of sibling books. R2 cover upload at import. Claude summary cached to DB. Full edit + manual entry forms.
Phase 2.5 — Series Tracker ✓
Progress bar per series, per-book status badges, cover thumbnails, collapsible list, one-click "Add to Library" on unowned entries. Books ordered by series position.
Phase 3 — Upcoming Releases ✓
Timeline/list grouped by month. Add via Google Books search or manual entry (title, author, date, ISBN, cover, notes). Delete. Frontend and backend fully wired.
Phase 4 — News Feed ✓
RSS fetch via node-cron (every 4 hours + startup). 90-day rolling retention. Source filter chips. Active sources: Tor.com, Locus Magazine, SFF World, The Wertzone.
Phase 5 — Polish ✓
Four library view modes (Grid, Shelf, List, By Author). Dark/light mode toggle with full MDC override coverage. Cover images at native proportions — no bands, no cropping. Paginated book list. Compact mobile-first Series Tracker. Author name normalisation. Rate limiting + zod input validation.
